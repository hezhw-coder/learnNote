### 3.4 CI 最小执行步骤

已新增 `.github/workflows/ci.yml`，最小执行步骤如下：

1. `backend` 作业：
   - `actions/setup-java@v4`
   - `mvn -B clean verify`
   - 上传 `backend/target/site/jacoco/`
2. `frontend` 作业：
   - `actions/setup-node@v4`
   - `npm ci`
   - `npm run check:ci`
   - 上传 `frontend/coverage/`
3. `compose-smoke` 作业：
   - 依赖 `backend` 与 `frontend` 作业先通过
   - 执行 `pwsh ./scripts/docker-smoke.ps1`
   - 自动拉起 `docker/docker-compose.yml`
   - 校验后端健康检查、前端首页、网关登录、`/api/auth/me`、`/oauth2/token`、`/open-api/v1/patients`、`/open-api/v1/medications`
   - 上传 `.artifacts/compose-smoke/`

### 3.5 覆盖率门禁基线

- 后端 `JaCoCo`：
  - `LINE >= 10%`
  - `BRANCH >= 5%`
- 前端 `Vitest`：
  - `statements >= 8%`
  - `functions >= 8%`
  - `lines >= 8%`
  - `branches >= 5%`
- 当前阈值定位为“最小非零门禁”，目标是先在 PR 流水线上形成真实拦截，再逐轮抬高。

### 3.6 失败排查入口

- `Flyway` 启动失败：
  - 检查 `backend/src/main/resources/db/migration/` 是否出现重复 `V*__*.sql`
  - 重点确认当前只保留一个生效的 `V5__*.sql`，安全加固脚本已顺延到 `V6`
- 后端测试失败：
  - 优先查看 `backend/target/surefire-reports/` 中首个失败用例
  - 若覆盖率目录缺失，确认 `jacoco-maven-plugin` 是否在 `verify` 阶段执行
- 前端测试失败：
  - 先执行 `npm run type-check` 定位类型错误
  - 若 `coverage` 失败，确认 `@vitest/coverage-v8` 已安装，且 `frontend/package-lock.json` 与 `package.json` 同步
 - 容器回归失败：
  - 先查看 `.artifacts/compose-smoke/compose-ps.log`
  - 再查看 `.artifacts/compose-smoke/compose-logs.log`
  - 若登录链路失败，优先检查 `frontend` 的 `/api` 与 `/oauth2` 反代是否仍指向 `backend`

## 4. Docker 与端到端回归步骤

建议按以下顺序执行：

1. 先执行自动化回归：
   - `cd frontend && npm run check:ci`
   - `cd backend && mvn clean verify`
2. 启动开发版或生产版容器：
   - 开发版：`docker compose -f docker/docker-compose.yml up -d --build`
   - 生产版：`docker compose -f docker/docker-compose.prod.yml --env-file docker/.env.prod up -d --build`
3. 登录管理台：
   - 开发版：`http://127.0.0.1:18081/`
   - 生产版：`https://mdc.localtest.me:18443/`
4. 验证认证安全闭环：
   - `POST /api/auth/login`
   - `POST /api/auth/refresh`
   - `POST /api/auth/logout`
   - `GET /api/auth/me`
5. 验证 ETL 主链路：
   - 创建带 `fieldBindings` 的 ETL 任务并执行
   - 确认 `cdm_patient`、`cdm_lab_result`、`cdm_medication_order` 样例数据可见
6. 验证报表主链路：
   - 创建或编辑模板
   - 配置筛选、参数、联动、布局
   - 保存草稿并发布
   - 执行预览、PDF、Excel
   - 创建调度并核对 `templateVersion`
7. 验证开放 API：
   - 通过 `/oauth2/token` 申请令牌
   - 调用患者、就诊、检验、用药、报表接口
   - 核对返回条数与 `ok rows=<n>` 日志
8. 验证系统管理：
   - 新建用户
   - 新建角色并分配权限
   - 修改关键系统参数
   - 查看审计日志
