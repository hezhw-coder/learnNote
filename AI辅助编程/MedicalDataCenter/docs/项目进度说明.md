# MedicalDataCenter 项目进度说明

## 1. 文档说明

本文档用于描述当前仓库已经实现的能力边界、交付状态和后续增强方向，内容以现有代码、Flyway 迁移、Docker 编排、测试资源和交付文档为准，不再保留历史任务流水账。

当前判断主要依据以下维度：

- 前端路由、页面与权限控制
- 后端模块、接口和业务链路
- 数据库迁移脚本与初始化数据
- Docker 部署、Nginx 网关和生产安全基线
- 自动化测试、回归脚本与交付文档

## 2. 总体结论

- 项目已完成 MVP 一期主干建设，并完成多轮计划内增强，当前处于“可运行、可部署、可联调、可回归”的稳定阶段。
- 管理端、开放 API、ETL、数据集、报表设计与调度、系统管理均已具备真实代码实现，不再是仅供演示的静态骨架。
- 当前 Flyway 迁移已线性演进到 `V13`，Docker 开发版和生产版编排、最小 CI、覆盖率入口与容器级 smoke 回归均已具备。
- 剩余工作主要集中在更高等级的生产化增强，而不是当前主流程缺失。

## 4. 已交付能力明细

### 4.1 工程与部署基础

- 前端采用 `Vite + Vue 3 + TypeScript + Element Plus`
- 后端采用 `Spring Boot + Maven`
- 开发版使用 `docker/docker-compose.yml` 直连前后端
- 生产版使用 `docker/docker-compose.prod.yml` 和 Nginx 统一暴露 HTTPS 入口
- 基础设施已接入 `TiDB + Redis + Flyway`
- 交付文档已覆盖部署、使用、升级、数据库结构、接口和验收记录

### 4.2 认证与权限

- 已实现平台账号登录、当前用户查询、刷新续期和服务端退出登录
- 已实现基于权限码的 RBAC 控制和前端菜单动态渲染
- 已实现登录失败计数、临时锁定、最小密码策略和审计日志记录
- 已支持 JWT 双密钥兼容验签、请求链路 `request_id` 贯通和生产安全基线校验

### 4.3 数据接入与标准化

- 已实现数据源新增、编辑、启停、测试连接和删除
- 已实现 ETL 任务配置、执行、运行记录和增量 checkpoint
- 已实现 `ODS -> CDM` 标准化写入
- 当前标准化主题包括：
  - `cdm_patient`
  - `cdm_encounter`
  - `cdm_lab`
  - `cdm_lab_result`
  - `cdm_medication_order`
- ETL 任务已支持 `fieldBindings` 语义绑定，标准化映射以 `field_bindings_json` 持久化

### 4.4 数据集与报表

- 已支持数据集列表、字段元数据和样本数据预览
- 报表模板已支持布局、组件、绑定、筛选、参数和联动配置
- 已支持报表预览、PDF 导出、Excel 导出和调度执行
- 已支持模板草稿/发布、版本冲突校验、模板生效版本追踪
- 已支持调度与快照记录模板版本和运行时参数，便于回溯

### 4.5 开放 API 与系统管理

- 开放 API 已支持客户端管理、scope 管理和 `/oauth2/token`
- 已开放患者、就诊、检验、用药医嘱、报表等查询链路
- 已支持按主题关键字段筛选、默认脱敏、访问日志与限流
- 系统管理已支持用户、角色、权限、系统参数和审计日志查询与维护

### 4.6 测试与交付

- 后端已具备认证、ETL、报表、开放 API、系统管理相关集成测试
- 前端已保留权限与报表 schema 的最小单测
- 已具备前后端覆盖率输出目录和最小阈值门禁
- 已配置 GitHub Actions 最小 CI 工作流
- 已提供 `tests/api`、Postman 集合和 `scripts/docker-smoke.ps1` 容器回归脚本

## 5. 当前交付状态

当前仓库已经具备以下交付特征：

- 可以通过 Docker 在本地完整启动
- 可以使用默认管理员账号完成登录和主流程演示
- 可以完成数据源配置、ETL 执行、数据集预览、报表预览/导出/调度、开放 API 调用
- 可以通过现有测试入口和交付文档完成最小回归验证
- 可以作为 MVP 演示版本、内部联调版本和后续二次开发基础仓库继续演进

## 6. 当前已知边界

当前仍存在但不阻塞交付的边界主要包括：

- ETL 主题仍可继续扩展到更多医疗域
- 报表设计器仍缺少更深层的低代码拖拽和复杂表达式能力
- 开放 API 仍可继续扩展更多真实主题、更细粒度 scope 与数据权限
- 生产级监控、告警、备份归档和 Secret 托管仍有增强空间
- 测试体系仍以最小回归为主，覆盖率和交互深度仍可继续提升

## 7. 建议后续方向

建议按以下优先级继续增强：

1. 扩展 ETL/CDM 医疗主题和标准化规则
2. 继续增强报表设计器的低代码能力和调度治理能力
3. 深化开放 API 的主题覆盖、脱敏策略和网关治理
4. 提高测试阈值、容器回归深度和 CI 必过门禁
5. 完善生产级监控、证书、密钥托管与运维体系

## 8. 一句话结论

当前 `MedicalDataCenter` 已完成 MVP 一期与计划内增强阶段的主要建设，达到“可运行、可部署、可联调、可回归、可继续增强”的现状，后续重点应转向生产化深水区能力而非基础功能补洞。
