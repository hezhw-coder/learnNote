# 医疗数据中心部署文档

## 1. 文档目标

本文档用于指导医疗数据中心 MVP 一期在开发、测试和演示环境中的容器化部署，覆盖以下交付目标：

- 采用 `Docker Compose` 一键拉起前端、后端、TiDB、Redis。
- 满足计划文件中“前后端分离 + Docker 部署 + MVP 一期”的实施要求。
- 为后续前端工程 `frontend/` 和后端工程 `backend/` 的接入提供统一交付规范。

## 2. 部署架构

本仓库当前交付的容器编排位于 `docker/docker-compose.yml`，整体部署拓扑如下：

| 组件 | 容器名 | 端口 | 说明 |
| --- | --- | --- | --- |
| Nginx + 前端静态资源 | `mdc-frontend` | `18081 -> 80` | 提供前端静态页面并反向代理后端接口 |
| Spring Boot 后端 | `mdc-backend` | `18080 -> 8080` | 提供管理端 API、开放 API、健康检查 |
| TiDB | `mdc-tidb` | `4000` / `10080` | 平台主业务库与标准化仓库主存储 |
| Redis | `mdc-redis` | `6379` | JWT 会话、限流、缓存 |
| TiDB 初始化 | `mdc-tidb-init` | 无 | 首次启动时自动建库 `medical_data_center` |

## 3. 前置条件

部署前请准备以下运行时：

- `Docker 24+`
- `Docker Compose v2+`
- 可访问外网的镜像拉取环境
- 至少 `4 CPU / 8 GB RAM / 30 GB` 可用磁盘

如需本地执行源码构建，还需准备：

- 前端：`Node.js 20+`、`npm 10+`
- 后端：`JDK 17`、`Maven 3.9+`

## 5. 环境变量

`docker/docker-compose.yml` 中使用的关键变量如下，可通过 PowerShell 环境变量、Shell 环境变量或 `.env` 文件注入：

| 变量名 | 默认值 | 说明 |
| --- | --- | --- |
| `MDC_DB_NAME` | `medical_data_center` | TiDB 数据库名 |
| `MDC_DB_USERNAME` | `root` | TiDB 用户名 |
| `MDC_DB_PASSWORD` | 空 | TiDB 密码 |
| `REDIS_PASSWORD` | `mdcRedis@123` | Redis 密码 |
| `MDC_JWT_SECRET` | `medical-data-center-docker-jwt-secret-2026` | JWT 签名密钥，生产环境必须覆盖 |
| `MDC_OAUTH2_ISSUER` | `http://localhost:8080` | OAuth2 签发方 |
| `MDC_ALLOWED_ORIGIN_PATTERNS` | `http://localhost:18081,...` | Docker 场景允许的浏览器来源地址 |

建议在正式环境覆盖以上默认值，避免使用示例密钥。

可先复制环境变量模板：

```bash
cp docker/.env.example docker/.env
```

## 6. 部署步骤

### 6.1 准备前后端构建产物

当 `frontend/` 与 `backend/` 工程落地后，优先执行根目录构建脚本：

Windows:

```powershell
pwsh -File .\scripts\build.ps1
```

Linux:

```bash
bash ./scripts/build.sh
```

脚本行为：

- 若存在 `frontend/package.json`，自动安装依赖并执行 `npm run build`。
- 若存在 `backend/pom.xml`，自动执行 `mvn clean package -DskipTests`。
- 默认继续执行 `docker compose build`。

### 6.2 启动容器

在项目根目录执行：

```bash
docker compose -f docker/docker-compose.yml up -d --build
```

如需强制重建容器并刷新最新配置，执行：

```bash
docker compose -f docker/docker-compose.yml down
docker compose -f docker/docker-compose.yml up -d --build --force-recreate
```

首次启动时系统会自动完成以下动作：

- 启动 `TiDB` 与 `Redis`
- 由 `mdc-tidb-init` 自动创建数据库 `medical_data_center`
- 后端执行 `Flyway` 初始化脚本
- 前端 `Nginx` 加载构建后的静态资源并反向代理 `/api`、`/open-api`、`/actuator`

### 6.3 查看状态

```bash
docker compose -f docker/docker-compose.yml ps
docker compose -f docker/docker-compose.yml logs -f backend
docker compose -f docker/docker-compose.yml logs -f frontend
```

### 6.4 访问入口

| 入口 | 地址 | 说明 |
| --- | --- | --- |
| 前端管理台 | `http://127.0.0.1:18081/` | Nginx 提供前端入口 |
| 后端 API | `http://127.0.0.1:18080/api` | 后端管理接口 |
| 开放 API | `http://127.0.0.1:18081/open-api/v1` | 第三方集成接口 |
| 健康检查 | `http://127.0.0.1:18080/actuator/health` | 后端健康状态 |
| Swagger UI | `http://127.0.0.1:18080/swagger-ui.html` | 后端接口调试页面 |
| TiDB Dashboard | `http://localhost:10080/status` | TiDB 状态页 |

默认演示账号：

- 用户名：`admin`
- 密码：`Admin@123`

## 7. 反向代理说明

Nginx 配置位于 `docker/nginx/default.conf`，包含以下路由策略：

- `/`：前端单页应用回退到 `index.html`
- `/api/`：转发到 `backend:8080/api/`
- `/open-api/`：转发到 `backend:8080/open-api/`
- `/actuator/`：转发到后端健康检查
- 为避免同源前端经反代访问后端时被误判为跨域，`Nginx` 转发时会移除 `Origin` 请求头

如需接入 HTTPS，建议在网关层补充：

- `443` 监听与证书挂载
- 强制 `HTTP -> HTTPS` 跳转
- `X-Forwarded-*` 头标准化
- 开放 API 白名单与 WAF 规则

## 8. 数据与持久化

当前编排使用以下命名卷：

| 卷名 | 用途 |
| --- | --- |
| `tidb-data` | TiDB 数据持久化 |
| `redis-data` | Redis AOF 持久化 |
| `backend-logs` | 后端日志目录 |
| `backend-exports` | 报表导出文件目录 |

建议将导出目录定期归档，并为 TiDB、Redis 补充独立备份任务。

## 9. 安全基线建议

结合计划文件中的安全要求，部署环境至少应落实：

- 覆盖默认的 `JWT` 密钥和 Redis 密码。
- 通过反向代理统一启用 `HTTPS`。
- 对 `/open-api/` 配置 IP 白名单、限流、访问日志。
- 对报表导出目录启用最小权限控制。
- 对 TiDB 和 Redis 端口进行内网隔离，避免公网暴露。

## 10. 故障排查

### 10.1 后端容器无法启动

检查项：

- `backend/target/*.jar` 是否存在
- `application-docker.yml` 是否已按约定读取 `MDC_*` 环境变量
- TiDB 与 Redis 是否已正常启动
- `mdc-tidb-init` 是否已成功执行建库
- 使用 `docker compose -f docker/docker-compose.yml logs --tail=120 backend` 查看 `Flyway` 和 `Tomcat` 启动日志

### 10.2 前端容器构建失败

检查项：

- `frontend/package.json` 是否存在
- `frontend/` 是否已生成可构建的 Vite 项目
- 是否存在私有依赖仓库访问限制

### 10.3 前端页面可打开但登录返回 403

检查项：

- 是否已使用当前文档中的高位端口 `18081`
- 前端容器是否已按最新 `docker/nginx/default.conf` 重建
- 后端容器是否已按最新 `application-docker.yml` 重建
- 浏览器是否残留旧的 `localStorage` 数据，可清理 `mdc-token`、`mdc-user` 后重试

推荐命令：

```bash
docker compose -f docker/docker-compose.yml up -d --build backend frontend
```

### 10.4 开放 API 无法访问

检查项：

- `docker/nginx/default.conf` 中 `/open-api/` 反向代理是否生效
- 后端是否启用 OAuth2/JWT
- Redis 限流规则是否误拦截

### 10.5 容器内服务正常但宿主机浏览器无法访问

若容器内 `wget http://127.0.0.1:8080/actuator/health` 正常、宿主机访问异常，优先检查：

- Docker Desktop 是否异常启用了代理或端口转发不稳定
- 是否已重启 Docker Desktop
- 是否使用高位端口 `18080/18081`
- Windows 本机是否存在安全软件、代理软件或回环过滤规则干扰
