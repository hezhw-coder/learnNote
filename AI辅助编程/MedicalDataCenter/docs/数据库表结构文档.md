# 医疗数据中心数据库表结构文档

## 1. 文档说明

- 项目名称：医疗数据中心 `MedicalDataCenter`
- 当前数据库名：`medical_data_center`
- 当前方言：`TiDB / MySQL 8` 兼容模式
- 结构来源：`backend/src/main/resources/db/migration/V1__init_schema.sql` ~ `V13__track_report_template_version_on_schedule_and_snapshot.sql`
- 当前范围：截至 `V13` 迁移脚本定义的业务表结构、演示数据与增强字段

说明：

- 本文档描述的是当前项目实际落库的业务表结构
- 物理外键未在脚本中显式创建，表间关系以“逻辑关系”方式维护
- `flyway_schema_history` 为 Flyway 自动维护的系统表，不属于业务建模表，但部署时会自动生成
- 为保留并行分支痕迹，仓库中保留了一个 `.bak` 迁移备份文件，但 Flyway 实际生效顺序已线性化为 `V1 -> V2 -> V3 -> V4 -> V5 -> V6 -> V7 -> V8 -> V9 -> V10 -> V11 -> V12 -> V13`

## 2. 模块划分总览

| 模块 | 表数量 | 主要表 |
| --- | ---: | --- |
| 系统与权限 | 8 | `sys_user`、`sys_role`、`sys_permission`、`sys_user_role`、`sys_role_permission`、`sys_audit_log`、`sys_parameter`、`auth_session` |
| 数据源与 ETL | 11 | `ds_source`、`ds_source_secret`、`etl_job`、`etl_job_run`、`etl_increment_checkpoint`、`ods_record`、`cdm_patient`、`cdm_lab_result`、`cdm_encounter`、`cdm_lab`、`cdm_medication_order` |

| 开放 API | 4 | `api_client`、`api_scope`、`api_access_log`、`api_rate_limit_rule` |
| 合计 | 29 | 全部业务表 |

## 3. 逻辑关系总览

### 3.1 权限域

- `sys_user` 与 `sys_role` 通过 `sys_user_role` 建立多对多关系
- `sys_role` 与 `sys_permission` 通过 `sys_role_permission` 建立多对多关系
- `sys_audit_log` 记录平台操作审计信息
- `sys_parameter` 保存平台可维护的非敏感系统参数
- `auth_session` 保存平台用户的服务端会话、刷新令牌摘要和注销状态

### 3.2 数据接入与标准化域

- `ds_source` 保存数据源基本信息
- `ds_source_secret` 以 `source_id` 一对一保存数据源密文密码
- `etl_job` 关联 `ds_source.id`
- `etl_job_run` 关联 `etl_job.id`
- `etl_increment_checkpoint` 以 `job_id` 一对一保存增量抽取游标
- `ods_record` 保存抽取后的原始记录，关联 `etl_job.id` 与 `etl_job_run.id`
- `cdm_patient` 保存标准化患者主题数据，关联 `source_job_id`
- `cdm_lab_result` 保存 ETL 检验结果主题数据，关联 `source_job_id`
- `cdm_medication_order` 保存 ETL 用药医嘱主题数据，关联 `source_job_id`
- `cdm_encounter`、`cdm_lab` 保存开放 API 演示使用的就诊与检验主题数据

### 3.3 数据集与报表域

- `meta_dataset` 定义数据集
- `meta_dataset_field` 通过 `dataset_code` 关联 `meta_dataset.code`
- `report_template` 通过 `dataset_code` 绑定数据集
- `report_snapshot`、`report_schedule` 通过 `template_id` 关联 `report_template.id`
- `notify_message` 保存站内消息通知

### 3.4 开放 API 域

- `api_client` 保存第三方客户端
- `api_scope` 定义开放接口作用域
- `api_access_log` 记录客户端访问日志
- `api_rate_limit_rule` 保存客户端维度的限流规则

## 6. 当前建模特点与建议

### 6.1 当前特点

- 使用逻辑外键而不是物理外键，便于快速迭代和跨库兼容
- 大字段 JSON 设计主要用于 ETL 原始数据与报表模板
- 当前已覆盖 `cdm_patient`、`cdm_lab_result`、`cdm_medication_order` 三个 ETL 标准主题，以及 `cdm_encounter`、`cdm_lab` 两个开放 API 演示主题
- 开放 API 的授权、作用域、访问日志、限流规则已具备基础闭环
- 系统管理已包含可审计的系统参数维护能力
- 报表模板的参数、布局、版本元数据主要存储在 `report_template.design_json` 中，`report_schedule` 与 `report_snapshot` 额外保留运行时参数和模板版本追溯字段
- Flyway 迁移已扩展到 `V13`，当前线性顺序为 `V1 -> V2 -> V3 -> V4 -> V5 -> V6 -> V7 -> V8 -> V9 -> V10 -> V11 -> V12 -> V13`

### 6.2 建议后续完善

- 为高频查询表补充业务索引，例如：
  - `etl_job_run(job_id, started_at)`
  - `ods_record(job_id, batch_run_id)`
  - `report_snapshot(template_id, created_at)`
  - `api_access_log(client_id, created_at)`
- 对逻辑关联字段补充唯一约束或联合索引
- 在后续版本中扩展更多医疗主题表，如就诊、检验、处方、检查等
- 对敏感数据表增加更明确的脱敏、加密和审计设计
