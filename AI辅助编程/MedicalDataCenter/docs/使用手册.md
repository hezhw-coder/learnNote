# 医疗数据中心使用手册

## 1. 手册范围

本文档描述医疗数据中心 MVP 一期的标准使用流程，覆盖计划文件中的四大核心业务域：

- 数据源连接管理
- 多源医疗数据抽取与标准化
- 在线报表设计与调度
- 开放 API 与第三方集成

本文档面向以下角色：

- 平台管理员
- 数据工程师
- 报表设计人员
- 第三方系统接入人员

## 2. 角色说明

| 角色 | 典型职责 |
| --- | --- |
| 平台管理员 | 用户、角色、权限、参数配置、审计查看 |
| 数据工程师 | 数据源接入、抽取任务、字段映射、数据集维护 |
| 报表设计人员 | 报表模板设计、预览、发布、导出 |
| 第三方接入方 | OAuth2 申请令牌、调用开放 API |

## 3. 登录与首页

### 3.1 登录

用户通过 `/login` 输入账号和密码登录，登录成功后系统返回 `JWT` 会话信息，并进入工作台。

当前 Docker 演示环境的标准访问方式如下：

- 前端地址：`http://127.0.0.1:18081/`
- 后端地址：`http://127.0.0.1:18080/`
- 默认管理员账号：`admin / Admin@123`

首次无法登录时，优先检查以下事项：

- 是否已按最新配置重建 `backend` 与 `frontend` 容器
- 浏览器 `localStorage` 中是否残留旧的 `mdc-token`、`mdc-user`
- 当前访问地址是否为最新高位端口 `18081`

建议首期启用以下能力：

- 首次登录修改密码
- 登录失败审计记录
- 管理员密码复杂度校验

### 3.2 工作台

工作台 `/dashboard` 推荐展示：

- 数据源总数、启用数、异常数
- ETL 任务执行次数、成功率、失败率
- 报表模板数量、调度任务数量
- 开放 API 调用量、限流命中次数

当前版本中，登录成功后会基于后端返回的权限码动态装载菜单与页面访问能力。

## 4. 数据源管理

对应页面：`/data-sources`

### 4.1 新增数据源

1. 点击“新增数据源”。
2. 选择数据库类型：`MySQL`、`PostgreSQL`、`SQL Server`、`Oracle`、`MongoDB`、`TiDB`。
3. 输入连接参数：
   - 数据源名称
   - 主机地址
   - 端口
   - 数据库名或服务名
   - 用户名
   - 密码
   - 连接属性
4. 点击“测试连接”。
5. 测试通过后保存。

当前版本说明：

- 已支持新增、编辑、删除、测试连接、启用停用等基础流程
- 连接信息会持久化保存到平台数据库
- 演示联调时建议优先使用 `TiDB/MySQL` 类型数据源

### 4.2 管理规则

- 敏感字段如密码必须加密存储。
- 删除采用软删除，不直接物理删除。
- 停用数据源后，不允许新任务继续调度。

### 4.3 建议维护字段

| 字段 | 说明 |
| --- | --- |
| 数据源编码 | 系统内唯一编码 |
| 数据源类型 | 六类强制适配源之一 |
| 连接状态 | 正常、异常、停用 |
| 最后测试时间 | 最近一次连通性测试时间 |
| 负责人 | 便于跨团队协作 |

## 5. ETL 抽取与标准化

对应页面：`/etl`、`/datasets`

### 5.1 创建抽取任务

1. 选择来源数据源。
2. 选择抽取对象表或集合。
3. 配置抽取方式：
   - 全量抽取
   - 增量抽取
4. 选择增量字段或游标策略。
5. 配置 ODS 表落地规则。
6. 配置字段映射、字典转换、清洗规则。
7. 保存并执行任务。

当前版本说明：

- 页面支持任务创建、执行与运行记录查看
- 后端已提供任务执行链路与运行日志查询接口
- MVP 阶段更适合演示标准化抽取流程，复杂异构源适配可继续扩展

### 5.2 标准化流程

标准化采用 `ODS -> CDM` 双层模型：

- `ODS`：保留原始或轻清洗数据
- `CDM`：统一为平台医疗标准模型

推荐首期标准主题：

- 患者
- 就诊
- 科室
- 医生
- 医嘱
- 检验
- 检查
- 药品

### 5.3 运维建议

- 全量任务建议在夜间执行。
- 增量任务建议配置重试与告警。
- 失败任务应保留游标与运行日志，避免重复入仓。

## 6. 数据集管理

对应页面：`/datasets`

数据集管理用于为报表设计器和开放 API 提供标准化访问入口，建议支持：

- 数据集目录与分类
- 字段元数据查看
- 血缘关系查看
- 样本数据预览
- 权限范围控制

使用建议：

- 对敏感字段增加脱敏标签。
- 对对外开放字段单独维护作用域。

当前版本说明：

- 数据集页面用于查看标准化主题数据与字段清单
- 后续可继续扩展更多医疗主题模型与字段血缘能力

## 7. 报表设计与任务

对应页面：`/reports/designer/:id`、`/reports/jobs`

### 7.1 新建报表模板

1. 进入报表设计器。
2. 选择数据集。
3. 从组件面板拖拽以下组件到画布：
   - 指标卡
   - 表格
   - 折线图
   - 柱状图
   - 饼图
4. 配置维度、指标、过滤条件。
5. 设置主题、标题、图例、坐标轴。
6. 保存模板并预览。

### 7.2 预览与导出

系统应保证同一份模板支持：

- 在线预览
- 导出 `PDF`
- 导出 `Excel`

建议在导出时记录：

- 模板版本
- 生成时间
- 操作人
- 参数快照

### 7.3 调度与通知

1. 创建报表调度任务。
2. 配置执行周期。
3. 选择导出格式。
4. 设置站内消息通知接收人。
5. 保存并启用。

邮件推送在 MVP 一期仅保留配置入口，不要求真实发送。

当前版本说明：

- 报表设计器支持模板保存、在线预览和导出入口
- 当前更适合演示报表配置与布局流程，不等同于成熟 BI 产品的完整拖拽能力

## 8. 开放 API 使用

对应页面：`/open-api`

### 8.1 客户端申请

1. 管理员创建 API 客户端。
2. 为客户端分配作用域。
3. 系统生成 `client_id` 与 `client_secret`。
4. 接入方使用 OAuth2 获取访问令牌。

当前访问入口：

- 管理端页面：`/open-api`
- 接口前缀：`/open-api/v1/*`
- Swagger 调试地址：`http://127.0.0.1:18080/swagger-ui.html`

### 8.2 调用流程

1. 申请访问令牌。
2. 在请求头中携带 `Authorization: Bearer <token>`。
3. 调用 `/open-api/v1/*` 接口。
4. 根据返回码与 `requestId` 排查问题。

演示环境中，可先使用管理员账号登录平台，再在开放 API 模块中查看客户端、作用域与示例请求。

### 8.3 合规要求

- 敏感字段默认脱敏。
- 所有访问写入审计日志。
- 每个客户端应设置限流规则。

## 9. 系统管理

对应页面：`/system`

系统管理建议包含：

- 用户管理
- 角色管理
- 权限点配置
- 审计日志查看
- 字典项管理
- 系统参数管理

推荐最小 RBAC 模型：

| 角色 | 权限建议 |
| --- | --- |
| 超级管理员 | 全量配置与审计查看 |
| 平台管理员 | 数据源、用户、角色、参数管理 |
| 数据工程师 | 数据源查看、ETL、数据集管理 |
| 报表设计师 | 报表模板、调度任务 |
| API 运维人员 | 开放客户端、日志、限流策略 |

当前版本说明：

- 系统管理已覆盖用户、角色、权限、审计等核心入口
- 权限控制采用后端权限码与前端动态路由结合的方式

## 10. 常见操作流程

### 10.1 首次接入一个医院 HIS 数据库

1. 新增数据源。
2. 完成连通性测试。
3. 创建 ODS 全量抽取任务。
4. 配置 CDM 字段映射。
5. 执行任务并检查结果。
6. 将数据集授权给报表模板或开放 API。

### 10.2 新增一个统计报表

1. 选择标准化数据集。
2. 设计图表布局。
3. 配置过滤器。
4. 预览数据是否正确。
5. 发布模板。
6. 配置导出或调度任务。

### 10.3 开放给第三方系统调用

1. 创建客户端应用。
2. 配置作用域。
3. 下发凭证。
4. 使用令牌测试接口。
5. 检查限流和审计日志。

### 10.4 Docker 演示环境首次启动后建议操作

1. 先确认后端健康检查：`http://127.0.0.1:18080/actuator/health`
2. 再打开前端首页：`http://127.0.0.1:18081/`
3. 使用 `admin / Admin@123` 登录
4. 进入数据源页面完成一条示例数据源配置
5. 再逐项验证 ETL、报表与开放 API 模块

## 11. 使用注意事项

- 生产环境必须更换默认密钥和默认密码。
- 对外开放接口必须通过 HTTPS 暴露。
- 抽取任务上线前必须完成样例数据验证。
- 报表模板发布前必须确认脱敏规则已生效。
- 高峰期避免执行大批量全量抽取。
- Docker 演示环境当前默认访问端口为 `18081/18080`，不是 `80/8080`。
- 若页面行为异常，可先清理浏览器 `localStorage` 中的 `mdc-token` 与 `mdc-user` 后重试。
